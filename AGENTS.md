# Working agreement for the reference-first rebuild

## Authority

The user's latest instructions and two attached character sheets define this rebuild. Read README.md, docs/PRODUCTION_PLAN.md, docs/ART_DIRECTION.md, docs/ACCEPTANCE.md, references/manifest.json, and status.json before starting a task.

Jew uses the black MISCHIEF STUDY sheet. Bo uses the lower row of CONCEPT 01. Do not use CONCEPT 01's gray, wide-eyed cat as a second target for Jew. Do not inspect or import rejected assets from recovery branches or folders for modeling guidance.

## Execution and collaboration

The user has explicitly requested agent work. Delegate bounded tasks with named owners and deliverables. Maintain one writer per master `.blend`; separate character owners may work concurrently after the shared review stage is fixed. Reference, pipeline, and read-only visual QA work can proceed alongside modeling. Transfer ownership explicitly before a different agent edits a master asset.

Each task handoff must record its stage, pet, reference/source hashes, owner, allowed paths, expected output and dependencies. Changes to shared cameras, stage lighting or materials require coordination before other artists use them.

Use Blender as the editable 3D authoring pipeline and retain the native .blend source required by this plan. Scripts may automate modeling operations, exports, and renders, but completion of a script is not evidence of likeness. Do not substitute an image generation output for a render of the actual source mesh. Do not build a runtime procedural animal as the final art asset.

## Reviews

Follow the stage order in the plan. Submit meaningful review packages; routine implementation details do not need repeated permission questions. User visual feedback decides shape, face and material acceptance. Record approvals only when actual feedback exists and bind them to the reviewed asset revision.

Do not claim an exact hidden-view reconstruction from perspective concepts. Present inferred profile/back geometry in real model views. Do not claim percentage likeness or physical-phone testing without defined measurements or actual tests.

## Scope

Prioritize character art. Create the minimal export viewer when required for pipeline proof; build the full product only after the art/export gates. Product requirements remain dark=Jew, light=Bo, mobile touch, prolonged-drag cat nibble and release, unrestricted Bo carry, no proactive cursor attack, digging and heart notes.

Keep credentials and machine-specific settings out of source, logs and review manifests. Do not bring recovery configuration into the new app without identifying a concrete need. Deployment is a later release task, not part of clearing the project or writing the plan.
